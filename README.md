## Sobre o projeto
O InovaHub é um projeto desenvolvido como parte da entrega da disciplina de desenvolvimento frontend. A ideia central é criar uma solução moderna, funcional e visualmente atraente, com foco em experiência do usuário, organização de informações e usabilidade em interfaces web.

O objetivo do projeto é demonstrar habilidades de criação de interfaces, estruturação de componentes, consumo de dados e entrega de uma aplicação com boa apresentação e navegação. A proposta pode ser adaptada ao contexto do hackathon, reunindo inovação, clareza e praticidade em um produto digital.

# Problema Identificado
Muitos projetos inovadores possuem dificuldades para encontrar colaboradores, parceiros e apoiadores, o que reduz suas chances de crescimento e impacto.
Além disso, informações sobre projetos ficam dispersas em diferentes plataformas, dificultando o encontro entre quem possui uma ideia e quem pode contribuir para sua execução.

## Objetivo
- Desenvolver uma interface responsiva e intuitiva;
- Aplicar boas práticas de frontend;
- Priorizar uma experiência agradável para o usuário;
- Entregar uma solução funcional com foco em valor e usabilidade.

# Requisitos Funcionais
### RF01 – Cadastro de Projetos
O sistema deve permitir que usuários publiquem projetos de inovação contendo informações como título, descrição, área de atuação, necessidades e contato.
### RF02 – Consulta de Projetos
O sistema deve permitir que usuários visualizem projetos cadastrados na plataforma.
### RF03 – Pesquisa de Projetos
O sistema deve permitir a busca de projetos por palavras-chave.
### RF04 – Filtragem de Projetos
O sistema deve permitir filtrar projetos por categoria, área de interesse ou ODS relacionada.
### RF05 – Visualização de Detalhes
O sistema deve exibir informações detalhadas de um projeto selecionado.
### RF06 – Demonstração de Interesse
O sistema deve permitir que usuários manifestem interesse em participar ou colaborar em um projeto.
### RF07 – Gerenciamento de Perfil
O sistema deve permitir que usuários visualizem e atualizem suas informações de perfil.
### RF08 – Dashboard do Usuário
O sistema deve disponibilizar um painel para acompanhamento dos projetos publicados e interesses recebidos.
### RF09 – Cadastro de Oportunidades
O sistema deve permitir que responsáveis por projetos publiquem oportunidades de colaboração.
### RF10 – Indicadores de Impacto
O sistema deve apresentar métricas sobre projetos cadastrados, colaboradores conectados e oportunidades geradas.
---
# Requisitos Não Funcionais
### RNF01 – Responsividade
A aplicação deve ser compatível com dispositivos desktop, tablet e smartphone.
### RNF02 – Facilidade de Uso
A interface deve ser intuitiva.
### RNF03 – Desempenho
As páginas devem carregar em até 3 segundos.
### RNF04 – Disponibilidade
A aplicação deve possuir disponibilidade mínima de 95%.
### RNF05 – Segurança
Os dados dos usuários devem ser protegidos contra acessos não autorizados.
### RNF06 – Acessibilidade
A plataforma deve seguir boas práticas de acessibilidade digital.
### RNF07 – Compatibilidade
A aplicação deve funcionar corretamente nos principais navegadores.
### RNF08 – Manutenibilidade
O código deve ser organizado e modularizado.
### RNF09 – Escalabilidade
A arquitetura deve permitir futuras integrações.
### RNF10 – Confiabilidade
O sistema deve preservar a integridade das informações.
